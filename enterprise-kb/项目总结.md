## 一、项目概述

在 Open WebUI 的 FastAPI + SvelteKit 架构上进行二次开发，独立设计并实现了企业级 RAG 知识库管理仪表板，涵盖 8 个功能模块，新增 33 个 API 端点，7 张数据库表，6 个前端页面。

## 五、技术亮点

1. **SQLite UNIQUE 约束冲突**：深入排查 3 种失败方案，最终用 `+10000 偏移 + 重新编号` 解决 chunk_index 中间态冲突
2. **双通道可靠性**：SSE 实时推送 + 3 秒轮询兜底，保证进度监控连接可靠性
3. **Prompt 闭环**：从模板编辑到聊天管道注入完整链路打通
4. **Agent 工作流真实 LLM 调用**：检索员调 query_collection + 分析员/汇报员调 DeepSeek API，变量在步骤间传递，检索结果带文档名+原文溯源
5. **`git checkout` 引发的连锁还原**：linter 干扰下多次修复→还原循环，最终采用追加式修改策略避免冲突
6. **FastAPI 路由匹配陷阱**：`/{id}` 先于 `/_workflows` 匹配导致 404，通过路由顺序调整解决
7. **测试体系落地**：为分块引擎编写 32 个 pytest 单元测试全绿，并沉淀 Claude Code 单元测试技能（pytest + vitest 双框架、自动生成报告）
8. **并发压测定位生产瓶颈**：Locust 模拟 100 并发 + Mock 外部 LLM/Embedding + PostgreSQL 多 worker 模拟生产，定位出 ChromaDB 多进程并发写损坏 HNSW 索引（`KB.file_add` 51.92% 失败）这一核心瓶颈，切远程 Chroma 后复测 `KB.file_add` 失败率归零，完成「发现→定位→修复→验证」闭环
9. **内存可视化诊断**：通过 Windows 提交限制（commit limit）发现内嵌 Chroma 在多 worker 下吃满 ~54GB 虚拟内存，从 73MB 释放到 54GB，量化了 PersistentClient 多进程部署的内存放大问题
